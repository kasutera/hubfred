# キャッシュ仕様

## パフォーマンス

- ワークフローがピッカー（`pr`、`is`、`gh`）とダッシュボード（`prs`、`iss`、`ghs`）のキャッシュを管理し、Alfred 標準の結果キャッシュは使わない。どちらも SQLite 形式と鮮度の判定方法を共用する。キャッシュファイルは画面ごとに分け、更新時はアトミックに置き換える。更新が重なった場合は、最後に置き換えに成功した結果が残る。
- 認証情報が一致し、キャッシュを保存してからの経過時間が `CACHE_FRESH_SECONDS` 未満なら、結果を再取得しない。再取得が必要でも、認証情報が一致し、更新開始時の経過時間が `CACHE_STALE_SECONDS` 未満ならキャッシュ済みの一覧を先に表示する。更新中は一覧を表示したままにし、取得に失敗しても認証情報が変わっていなければ表示を維持する。使えるキャッシュがなければ新しい結果を待ち、取得に失敗したらエラーを表示する。期限切れでもキャッシュは削除しない。閾値はどちらも [cache-decisions.sh](../workflow/prs.alfredui/cache-decisions.sh) で定義する。
- ピッカーに古い一覧を表示した場合は Script Filter を一度だけ再実行して一覧を更新する。
- ダッシュボードは起動時に一覧だけを読み込む。その後の非同期処理ではキャッシュのメタデータだけを読み取って再取得するかどうかを決める。プレビューは URL にインデックスを付けた別テーブルから選択項目の本文を読み込む。本文の読み込みに通信は発生しない。
- 生成済みの Octicon の PNG は `octicons-v5` にキャッシュされ、アカウントを問わず再利用される。

## セキュリティ

- キャッシュキーには `github.com` に使用するトークンの SHA-256 ハッシュを使う。トークンは `GH_TOKEN`、`GITHUB_TOKEN` の順に確認し、最初に見つかった空でない値を使う。どちらも空なら、ローカルで実行した `gh auth token --hostname github.com` の出力を使う。トークンそのものは保存せず、ハッシュだけを保存する。元のトークンは環境変数 `GH_TOKEN` で `search.sh` に渡す。
- ピッカーもダッシュボードも、認証情報が一致するキャッシュだけを使う。認証情報を解決できない場合や更新中に変わった場合は、古い一覧を消してエラーを表示する。ダッシュボードではプレビューも消去する。切り替え前の認証情報で取得した結果は表示も保存もしない。
- 一覧とダッシュボードの本文は暗号化せずに保存する。保存先は `$alfred_workflow_cache`、未設定の場合は `$HOME/Library/Caches/jp.kasutera.hubfred`。新規のキャッシュディレクトリとデータベースファイルは `umask 077` で作成し、既存のディレクトリの権限は変更しない。
- 撮影用ワークフローは本番用とは別の Bundle ID を持ち、キャッシュは `$HOME/Library/Caches/org.hubfred.screenshots` に保存する。合成データを使用し、GitHub には接続しない。
