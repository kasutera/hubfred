# キャッシュ仕様

## パフォーマンス

- **ピッカー（`pr`、`is`）：** Alfred は検索結果を30秒間キャッシュする。`loosereload` により、キャッシュ済みの結果を表示したままバックグラウンドで更新できる。
- **ダッシュボード（`prs`、`iss`）：** それぞれの SQLite キャッシュは `dashboard-v3.sqlite3` と `issues-dashboard-v3.sqlite3`。起動時は一覧だけを先に読み込み、非同期の更新処理はキャッシュのメタデータだけを見て取得の要否を決める。プレビューは選択した項目の本文を、URL にインデックスを付けた別テーブルから取得する。通信は発生しない。
- **ダッシュボードの有効期間：** 認証情報が一致するキャッシュは、保存から30秒未満なら再取得しない。30秒以上10分未満なら更新中もキャッシュ済みの一覧を表示し、認証情報が変わらず取得に失敗した場合も表示を維持する。認証情報が一致する10分未満のキャッシュがなければ、新しい結果を待ち、取得に失敗した場合はエラーを表示する。期限切れでもキャッシュは削除されない。
- **キャッシュの更新：** データベースをアトミックに置き換え、一覧と本文を同時に切り替える。重複する更新は独立して実行され、最後に置き換えに成功した結果が残る。
- **アイコン：** 生成済みの Octicon の PNG は `octicons-v5` にキャッシュされ、アカウントを問わず再利用される。

## セキュリティ

- **ダッシュボードのキャッシュキー：** `github.com` に使用するトークンの SHA-256 ハッシュをキーとする。トークンは、空でない `GH_TOKEN`、`GITHUB_TOKEN`、ローカルで実行した `gh auth token --hostname github.com` の出力の順に採用する。キャッシュに保存するのはハッシュのみ。元のトークンは環境変数 `GH_TOKEN` で `search.sh` に渡す。
- **ダッシュボードの認証分離：** 現在の認証情報に対応するキャッシュだけを使う。認証情報を取得できない場合や更新中に認証情報が変わった場合は、一覧とプレビューを消去してエラーを表示し、取得した結果はキャッシュしない。
- **ピッカーの制約：** Alfred のピッカーキャッシュは認証情報ごとに分離されない。GitHub CLI のアカウントを切り替えた後は、Alfred で `reload` を実行する。
- **ローカル保存：** ダッシュボードの一覧と本文は暗号化せずに保存する。保存先は `$alfred_workflow_cache`、未設定の場合は `$HOME/Library/Caches/jp.kasutera.hubfred`。新規のキャッシュディレクトリとデータベースファイルは `umask 077` で作成し、既存のディレクトリの権限は変更しない。
- **スクリーンショット用の分離：** 撮影用ワークフローは本番用とは別の Bundle ID と `$HOME/Library/Caches/org.hubfred.screenshots` を使う。合成データを使用し、GitHub には接続しない。
