# キャッシュ仕様

## パフォーマンス

- ピッカーとダッシュボードのキャッシュはワークフローが SQLite に保存し、Alfred 標準の結果キャッシュは使わない。絞り込み付きピッカーはダッシュボードの設定にかかわらず、広い範囲のキャッシュを使う。ダッシュボードがこのキャッシュを共用するのは取得上限が最大で期間指定がない場合だけ。それ以外は、ダッシュボードの種類ごとに1つのキャッシュを持ち、設定値が一致したときだけ使う。保存時はファイルをアトミックに置き換える。
- 認証情報が一致し、保存から `cacheFresh` 未満なら再取得しない。`cacheStale` 未満なら更新中もキャッシュ済みの一覧を表示できる。閾値は [store.go](../cmd/dashboard/store.go) で定義する。期間を指定したダッシュボードでは、表示時点で対象期間から外れた行をキャッシュから読み込んでも表示しない。
- 絞り込み付きピッカーはキャッシュから一覧だけを読み、条件に合う項目を更新順に表示する。古い一覧やキャッシュ未取得の一覧を更新するときは、Alfred が Script Filter を一度だけ再実行する。
- ダッシュボードに使えるキャッシュがなければ、条件に合う入力なしピッカーの結果を検索中に仮表示できる。各検索の先頭ページが揃ったら一覧を差し替え、続きがあれば設定した上限まで取得する。SQLite に保存する前に一覧を表示し、仮一覧や途中までの結果でキャッシュを置き換えない。
- 検索結果は先頭ページから本文を含む。プレビューはキャッシュの保存後に `bodies` テーブルから選択した項目の本文を URL で読み込む。追加の通信はしない。
- 生成済みの Octicon の PNG は `octicons-v5` にキャッシュされ、アカウントを問わず再利用される。

## セキュリティ

- キャッシュキーには `github.com` に使用するトークンの SHA-256 ハッシュを使う。トークンは `GH_TOKEN`、`GITHUB_TOKEN` の順に確認し、最初に見つかった空でない値を使う。どちらも空なら、ローカルで実行した `gh auth token --hostname github.com` の出力を使う。トークンそのものは保存せず、ハッシュだけを保存する。Go の処理は元のトークンを環境変数 `GH_TOKEN` で GitHub CLI に渡す。
- ピッカーとダッシュボードは認証情報が一致するデータだけを再利用する。ダッシュボードは検索の各段階と保存前に認証情報を確認する。認証情報を解決できない場合や更新中に変わった場合は、一覧とプレビューを消して取得中の結果を破棄する。
- 一覧とダッシュボードの本文は暗号化せずに保存する。保存先は `$alfred_workflow_cache`、未設定の場合は `$HOME/Library/Caches/jp.kasutera.hubfred`。新規のキャッシュディレクトリとデータベースファイルには現在のユーザーだけがアクセスできる。既存のディレクトリの権限は変更しない。
- 撮影用ワークフローは本番用とは別の Bundle ID を持ち、キャッシュは `$HOME/Library/Caches/org.hubfred.screenshots` に保存する。合成データを使用し、GitHub には接続しない。
